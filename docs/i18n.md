# Internacionalización (i18n)

Idiomas: **es** (por defecto y de reserva) y **en**. Preparado para añadir
catalán, euskera y valenciano (no están añadidos). Stack: `i18next` +
`react-i18next`, textos estáticos en JSON (sin backend ni carga diferida).

Código en `src/lib/i18n/`, textos en `src/locales/<idioma>/<namespace>.json`.

## Reglas rápidas

1. **Todo texto visible → `t('clave')`**: etiquetas, placeholders, `aria-label`,
   `title`, `alt`, toasts, mensajes de error, metadata. Lo que escribe el
   usuario (nombres, notas, títulos de tareas propias…) se muestra tal cual.
2. Escribe SIEMPRE el texto en `es` y en `en` a la vez. Si falta en `en`, se
   muestra el español (fallback), pero no debe quedar así.
3. No crees ni edites los JSON de otro namespace (ver tabla).
4. No uses `"es-ES"` ni `toLocaleString` a mano: usa los helpers de formato.

## Namespaces y dueños

Un fichero por namespace e idioma. Cada agente/feature es dueño de los suyos;
si necesitas un texto de otro namespace, usa `common` o pide la clave al dueño.

| Namespace | Contenido |
|---|---|
| `common` | Cabecera, tema, idioma, pie, botones/acciones genéricas (guardar, cancelar…), metadata raíz, `date.none` |
| `landing` | Landing (`src/app/page.tsx`) |
| `auth` | Login, registro, guardia de sesión (`components/auth`) |
| `dashboard` | Panel de inicio |
| `onboarding` | Alta de plan (`/nuevo-plan`) |
| `plan` | Resumen del plan, fases, UI de pasos y tareas (no los textos base) |
| `steps` | Secciones y tareas BASE (ver más abajo) |
| `vendors`, `guests`, `budget`, `timeline`, `ceremony`, `honeymoon`, `invitation` | Cada herramienta |
| `tools` | `planTools.*`, `stationery.*`, `appointments.*`, `members.*`, `ideas.*` (un grupo de primer nivel por herramienta) |
| `errors` | Errores transversales (`firebase.*` ya existe), 404/500 |

La lista de namespaces vive en `NAMESPACES` (`src/lib/i18n/config.ts`) y cada
JSON se importa en `src/lib/i18n/resources.ts`. Un namespace nuevo = fichero
vacío `{}` en cada idioma + una línea en ambos sitios.

## Claves

- Anidadas, en inglés y descriptivas: `header.login`, `vendors.form.title`,
  `form.fields.email.label`. Sin espacios; agrupa por pantalla/componente y luego
  por rol (`title`, `description`, `actions.save`, `empty.title`…).
- **Interpolación** `{{name}}`: `"userMenu": "Menú de {{name}}"` →
  `t('header.userMenu', { name })`. El escape lo hace React (no hay `escapeValue`).
- **Plurales** con sufijos `_one` / `_other` y la variable `count`:
  `"guests_one": "{{count}} invitado"`, `"guests_other": "{{count}} invitados"` →
  `t('summary.guests', { count: n })`.
- **Texto con elementos** (`<code>`, enlaces): `<Trans>` con marcas en el JSON:
  `"msg": "Añade <code>.env.local</code>"` →
  `<Trans i18nKey="firebaseNotConfigured.guard" ns="auth" components={{ code: <code /> }} />`.
- Las claves que se construyen en código (`t(\`features.${key}.title\`)`) deben
  existir para todos los valores posibles.

## Cliente (componentes `"use client"`)

```tsx
import { useTranslation } from "react-i18next";

const { t } = useTranslation("vendors");        // namespace por defecto del componente
t("form.title");
t("common:actions.save");                        // otro namespace: prefijo "ns:"
const { t } = useTranslation(["vendors", "common"]); // varios: el primero es el por defecto
```

`useLanguage()` (de `@/lib/i18n/provider`) devuelve `{ lang, locale, setLang, languages }`.
El idioma se guarda en `localStorage` y en la cookie `tubodadiy-lang` (misma
clave, `LANG_KEY`). Los componentes fuera de `<I18nProvider>` (p. ej.
`global-error.tsx`, que sustituye al layout raíz) no tienen traducciones: dales
el texto de otra forma.

## Servidor (server components, route handlers, metadata)

```ts
import { getRequestLang } from "@/lib/i18n/request";   // lee la cookie (solo servidor)
import { getServerT } from "@/lib/i18n/server";         // isomórfico, lee los mismos JSON

const lang = await getRequestLang();
const t = getServerT(lang, "auth");
t("login.meta.title");
```

`generateMetadata` debe usar esto (ver `app/layout.tsx`, `app/login/page.tsx`).
Importante: el layout raíz lee la cookie, así que **toda la app se renderiza
bajo demanda** (no hay páginas estáticas); a cambio el HTML ya sale en el
idioma correcto, sin parpadeo y con `<html lang>` correcto. Al cambiar de idioma
el proveedor guarda la cookie y hace `router.refresh()` para refrescar la
metadata. Un `<script>` en el `<head>` (`LANG_INIT_SCRIPT`) solo cubre el caso
de cookie borrada con `localStorage` intacto. Para el idioma de un dato que no
viene de la cookie (p. ej. invitación pública), pasa `lang` explícito.

## Formatos (Intl según idioma)

Todo en `src/lib/i18n/format.ts`; todas las funciones aceptan `lang` y, si
falta, usan español:

| Función | Uso |
|---|---|
| `formatMoney(n, lang)` / `formatCurrency(n, lang)` (utils) | euros sin decimales, miles siempre agrupados |
| `formatNumber(n, lang, opts?)` | números |
| `formatDateValue("YYYY-MM-DD" \| Date, lang, opts?)` | fecha larga o con tus `opts`; `null` si no es válida |
| `formatDate(value, lang)` (utils) | fecha larga o «Sin fecha» / «No date» |
| `dateFormatter(lang, opts)` / `numberFormatter(lang, opts)` | `Intl` cacheado para listas grandes |
| `localeOf(lang)` | locale BCP-47 (`es-ES`, `en-GB`) |

En componentes: `const { lang } = useLanguage(); formatCurrency(x, lang)`.
Las funciones de formato con `"es-ES"` fijo que aún quedan en otros ficheros
(`budget-math`, `timeline-model`, `invitation-*`, `onboarding-model`, `itinerary`,
`venue-discovery`) las migra el dueño de cada área al usar estos helpers.
`getFirebaseErrorMessage(error, lang)` también acepta idioma. `parseAmount`
acepta formato español; si se necesita entrada en inglés, ampliarla ahí.

## Textos base guardados en Firestore (steps)

Las secciones y tareas base se guardan **en español** dentro de cada plan
(`PlanStep.title/description`, `StepTask.title`, con `category` y `auto`).
No se cambian los datos: al **mostrarlas** se traducen según su clave, y si el
usuario las editó o las creó, se muestran tal cual.

En `src/lib/steps.ts` (con `t` de `useTranslation()` o `getServerT()` de
cualquier namespace; las funciones fuerzan `ns: "steps"`):

```ts
displayStepTitle(step.category, t, step.title);          // "Lugar" -> "Venue"; "Mi sitio" -> "Mi sitio"
displayStepDescription(step.category, t, step.description);
displayTaskTitle(step.category, task, t);                // task = { title, auto? }
```

- La clave sale de `category` (sección) y de `auto` de la tarea o, si no
  tiene, de su título base (`MANUAL_TASK_KEYS`); también reconoce títulos
  legacy (`legacyTaskTitle`, `RENAMED_AUTOS`, títulos antiguos de sección) y
  tareas guardadas sin `auto` (`baseTaskAuto`).
- Textos en `src/locales/<lang>/steps.json`:
  `sections.<category>.title | description | tasks.<auto-o-slug>`.
- Si añades una sección/tarea base nueva en `STEP_DEFINITIONS`, añade su
  traducción en TODOS los idiomas (`steps.json`) y, si no lleva `auto`, su slug
  en `MANUAL_TASK_KEYS`.
- Los componentes que pintan pasos/tareas (plan, dashboard, ideas…) deben
  usar estas funciones en lugar de `step.title` / `task.title` directos.
  Aún no están migrados: lo hace el dueño de cada uno.
- Lo mismo vale para cualquier otro texto base guardado: traducir por clave,
  nunca por el texto guardado, y mostrar el original si no coincide.

## Selector de idioma

`LanguageSwitch` (`src/components/language-switch.tsx`): rectangular, bloque
deslizante (`--ease-gentle`, sin transición con `prefers-reduced-motion`),
radios nativos con `role="radiogroup"` (flechas del teclado). Mismo alto que
`ThemeToggle` (40 px, 44 en táctil). Ya está en `AppHeader`, la cabecera de la
landing y `AuthShell` (login/signup). Se adapta solo a `LANGUAGES`; con más de
~4 idiomas habrá que revisar el ancho en 375 px.

## Añadir un idioma nuevo (p. ej. `ca`)

1. Copia `src/locales/es/` a `src/locales/ca/` y traduce los 16 JSON.
2. En `src/lib/i18n/resources.ts`: importa los 16 JSON y añade el bloque `ca: {…}`
   (el `satisfies` falla si falta algún namespace).
3. En `src/lib/i18n/config.ts`: añade `{ code: "ca", name: "Català", short: "CA", locale: "ca-ES" }`
   a `LANGUAGES` (`valencià` usaría `ca-ES-valencia`; euskera `eu-ES`).
4. Nada más: proveedor, cookie, selector, `getServerT` y formatos leen `LANGUAGES`.
   Comprueba el selector en 375 px y que `steps.json` tenga todas las secciones.
